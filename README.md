# Log Monitoring System

A distributed log monitoring system built with **Java**, **Apache Kafka**, and **PostgreSQL**.

This project is being developed as a technical assessment to demonstrate software engineering principles, modular architecture, clean code practices, and event-driven system design.

---

# Project Overview

The system monitors log files generated by different application components, converts log entries into structured events, publishes them to Apache Kafka, evaluates configurable monitoring rules, stores generated alerts in PostgreSQL, and exposes them through a REST API.

The architecture focuses on simplicity, maintainability, clear separation of responsibilities, and avoiding unnecessary architectural complexity.

---

# Project Objectives

* Monitor log files from multiple application components.
* Parse log entries into structured domain objects.
* Publish events to Apache Kafka.
* Evaluate configurable monitoring rules.
* Generate alerts when rules are violated.
* Persist alerts in PostgreSQL.
* Provide a REST API for retrieving alerts.
* Maintain a modular and extensible architecture.

---

# Project Architecture

The project follows a **Maven Multi-Module** architecture consisting of two executable modules and one shared module.

```text
log-monitoring-system/
│
├── pom.xml
├── README.md
├── docker-compose.yml
│
├── config/
│   ├── application.properties
│   └── rules.json
│
├── adr/
│   └── 0001-architecture-decisions.md
│
├── shared/
│
├── file-ingestor/
│
└── rules-evaluator/
```

## Module Responsibilities

### shared

Contains the shared domain model and common contracts used by other modules.

Responsibilities:

* Shared domain entities
* Common interfaces
* Avoid cyclic dependencies

---

### file-ingestor

Responsible for monitoring log files and publishing log events to Kafka.

Responsibilities:

* Watch log directory
* Process existing files at startup
* Detect newly created log files
* Parse log entries
* Publish events to Kafka
* Delete processed files only after successful delivery

---

### rules-evaluator

Responsible for consuming log events, evaluating monitoring rules, generating alerts, storing them, and exposing REST endpoints.

Responsibilities:

* Consume Kafka messages
* Load monitoring rules
* Evaluate rules
* Generate alerts
* Store alerts in PostgreSQL
* Provide REST API

# Architecture Principles

The project follows the following design principles:

* Separation of Responsibilities (SRP)
* Low coupling between modules
* Modular architecture
* Event-driven communication
* Simple and maintainable design
* Avoidance of unnecessary design patterns and over-engineering

Complex architectural patterns such as Hexagonal Architecture, CQRS, and Event Sourcing are intentionally omitted because they do not provide sufficient value for the scope of this project.

---

# Architecture Decisions

Important architectural decisions are documented in the `adr/` directory.

The first Architecture Decision Record (ADR) explains:

* Why Maven Multi-Module architecture was selected.
* Why Kafka is used for communication.
* Why unnecessary architectural complexity was avoided.
